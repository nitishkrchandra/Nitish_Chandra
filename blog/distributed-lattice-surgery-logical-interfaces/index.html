A remote logical gate is more than a remote physical gate

Distributed lattice surgery, logical parity measurements and noisy interfaces

A remote physical CNOT can be performed using entanglement, local operations, measurements and classical feedforward. A fault-tolerant logical operation requires additional protection. It may involve many physical qubits, repeated check measurements, decoder output and correction tracking. The distinction matters whenever logical blocks live on different QPUs.

How lattice surgery works

Surface-code lattice surgery manipulates the stabilizer measurements along boundaries of encoded patches. Joint logical measurements such as X⊗X or Z⊗Z, together with preparation and feedforward, can implement logical operations. If the patches are on different processors, measurements across the joining boundary need a physical remote-interaction protocol.

The seam changes the logical noise

The boundary shared by two patches is often called a seam. A remote seam may be noisier than the rest of the code because it relies on imperfect Bell pairs and additional communication. Our study of distributed lattice surgery considers an XX-merge of rotated surface-code patches, with a geometry that tracks the bulk and seam contributions to logical errors. The resulting finite-size analysis is intended to characterize a specific logical primitive under stated assumptions.

The fidelity of the remote resource alone does not determine the logical outcome. Bell-pair generation may take time, causing data qubits to wait while undergoing memory noise. Limited communication qubits can also force syndrome measurements to be serialized. This creates a fidelity–latency–resource tradeoff that must be evaluated at logical level.

Code-specific logical instruction sets

The choice of code also matters. Some logical gates may be transversal, whereas others require surgery, injection, code conversion or special ancillary states. The Eastin–Knill restriction rules out a universal transversal set for the relevant class of finite-dimensional error-detecting codes. A distributed compiler cannot therefore assume that all logical instructions use the same remote-gate pattern.

Research outlook

For comparing modular architectures, I would measure one complete logical instruction: the fault-tolerant circuit, entanglement consumption, correction rounds, time and failure probability. A good remote physical gate is only the beginning of that analysis.
