A remote logical gate is more than a remote physical gate

Distributed lattice surgery, logical parity measurements and noisy interfaces

A remote physical CNOT can be performed using entanglement, local operations, measurements and classical feedforward. A fault-tolerant logical operation requires additional protection. It may involve many physical qubits, repeated check measurements, decoder output and correction tracking. The distinction matters whenever logical blocks live on different QPUs. A physical operation's fidelity therefore cannot substitute for an estimate of the failure probability of the complete encoded procedure.

What is a joint logical measurement?

Consider two encoded qubits, A and B. A joint measurement of XAXB answers whether their logical X parities agree or disagree. Its result is a single sign, +1 or −1. This does not reveal each encoded qubit’s individual X value. Carefully chosen sequences of such parity measurements, together with auxiliary logical states and Pauli-frame updates, can implement entangling operations without directly exposing the logical state to an unprotected gate.

The equation is compact; implementing the measurement is not. In lattice surgery, the outcome is assembled from stabilizer information gathered over a fault-tolerant measurement procedure. A boundary operation must be repeated and decoded so that physical measurement errors do not immediately turn into incorrect logical feedforward.

How lattice surgery works

Surface-code lattice surgery manipulates the stabilizer measurements along boundaries of encoded patches. Joint logical measurements such as X⊗X or Z⊗Z, together with preparation and feedforward, can implement logical operations. If the patches are on different processors, measurements across the joining boundary need a physical remote-interaction protocol.

How distribution changes the seam

When the two patches live on different QPUs, a check along the joining seam can involve physical qubits that cannot interact directly. An entanglement-assisted measurement circuit replaces the local check circuit. Its failures can manifest as data errors, measurement errors, or correlated detector events. The effective seam noise therefore depends on the whole procedure, not merely the original Bell-pair infidelity.

Our distributed lattice-surgery analysis isolates how noise along the seam changes logical performance for a specified XX-merge geometry. The important interpretation is comparative: an increase in seam noise can change which error chains dominate the logical failure probability and whether increasing a geometric parameter gives the expected protection. The result is not a universal statement about every network protocol.

The seam changes the logical noise

The boundary shared by two patches is often called a seam. A remote seam may be noisier than the rest of the code because it relies on imperfect Bell pairs and additional communication. Our study of distributed lattice surgery considers an XX-merge of rotated surface-code patches, with a geometry that tracks the bulk and seam contributions to logical errors. The resulting finite-size analysis is intended to characterize a specific logical primitive under stated assumptions.

The fidelity of the remote resource alone does not determine the logical outcome. Bell-pair generation may take time, causing data qubits to wait while undergoing memory noise. Limited communication qubits can also force syndrome measurements to be serialized. This creates a fidelity–latency–resource tradeoff that must be evaluated at logical level.

Time is part of the logical gadget

A logical merge has both spatial and temporal extent. If a remote check must be performed repeatedly and entanglement generation is probabilistic, the syndrome schedule can stall. That stall matters even if the Bell pair that eventually arrives is high fidelity: data continue to accumulate memory errors while awaiting the next operation.

For useful architecture comparisons, one should report the failure probability of a complete joint measurement together with its latency and resource cost. Two protocols may achieve similar physical gate fidelity but have different logical error probabilities because one introduces longer memory exposure or more correlated errors.

Code-specific logical instruction sets

The choice of code also matters. Some logical gates may be transversal, whereas others require surgery, injection, code conversion or special ancillary states. The Eastin–Knill restriction rules out a universal transversal set for the relevant class of finite-dimensional error-detecting codes. A distributed compiler cannot therefore assume that all logical instructions use the same remote-gate pattern.

Beyond a single code family

Lattice surgery is not the only way to interact logically encoded blocks. Depending on the code, alternatives include transversal logical gates, code switching, teleportation through encoded resources and magic-state-assisted non-Clifford operations. These alternatives place communication and ancilla demands in different places. A compiler must know what operations the chosen code actually supports rather than simply translating every high-level gate into the same remote physical primitive.

The architectural question

For me, the useful abstraction is a logical interface contract: its supported operation, code compatibility, required entangled resources, space-time schedule, decoder assumptions and logical failure behavior. Once interfaces are characterized this way, modular architectures can be compared as systems rather than as collections of nominally equivalent Bell links.

Spatial and temporal protection

In a code-capacity picture, distance describes the minimum weight of a logical Pauli operator. A surgery procedure is a circuit that extends through time. A faulty check readout may appear as a detection event between measurement rounds, and repeated measurements allow a decoder to distinguish physical faults from readout faults. The effective protection of a merge therefore depends on both its patch geometry and its syndrome history.

For a distributed seam, the logical failure mechanisms are especially sensitive to the remote protocol. A Bell-pair imperfection can translate to data or readout errors; a late pair can add idle errors; a shared failure event can produce correlated detector outcomes. Simply labeling the interconnect with a physical fidelity does not reveal which of these mechanisms dominates the decoded logical operation.

To compare two interfaces meaningfully, one should fix the same encoded operation and target error budget, then measure its failure probability, latency distribution, consumed entanglement and communication-qubit occupancy. Even when a more elaborate purification procedure produces a better pair, the extra waiting could erode its advantage. It is the complete, decoded logical instruction that matters.

Research outlook

For comparing modular architectures, I would measure one complete logical instruction: the fault-tolerant circuit, entanglement consumption, correction rounds, time and failure probability. A good remote physical gate is only the beginning of that analysis. Reporting the logical instruction's latency distribution is also important because a slow remote interface can introduce additional idle errors elsewhere in the computation.
