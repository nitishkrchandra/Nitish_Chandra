Compilation and scheduling · November 2026 · 10 min read

From logical circuits to networked execution

Why mapping a logical circuit is more than minimizing remote gates

A logical quantum circuit is an abstract program. A real modular quantum computer has a limited number of encoded blocks, check ancillas, en­tan­gle­ment-generation ports and com­mu­ni­ca­tion links. Trans­lat­ing the logical program into an executable fault-tolerant schedule requires an ar­chi­tec­ture-aware com­pi­la­tion stack. The compiler must account for which logical in­struc­tions the code supports and how each in­struc­tion is lowered to physical operations and mea­sure­ments.

The right level of compilation

Gate par­ti­tion­ing is a useful starting point, but a fault-tolerant in­struc­tion may be a complex gadget rather than a single physical gate. A code's supported logical gates must first be determined. A parity mea­sure­ment or code-surgery operation has its own ancillary qubits, repeated mea­sure­ments and decoding de­pen­den­cies. These details determine what the network needs to deliver.

From a program to an executable fault-tolerant plan

A dis­trib­uted compiler cannot be understood only as a circuit partitioner. A logical circuit is made of encoded operations, each of which may require many physical gates, ancillas, syndrome mea­sure­ments and classical feed­for­ward. The available logical in­struc­tions depend on the chosen error-correcting code. A parity-mea­sure­ment procedure for surface-code patches is not equivalent to a trans­ver­sal operation on another code; non-Clifford gates may introduce further resource-state requirements.

This suggests a broad com­pi­la­tion pipeline: first determine the logical in­struc­tion set supported by the code, then lower the algorithm into implementable fault-tolerant gadgets, assign logical data and ancillary resources to processors, reserve com­mu­ni­ca­tion resources, and assess the resulting logical re­li­a­bil­i­ty. The purpose is not to assume one perfect remote gate for every abstract gate, but to account for how the logical in­struc­tion is actually im­ple­ment­ed.

Network operations are not free

Our scheduling work investigated resource-limited network operations following par­ti­tion­ing, comparing con­strained scheduling approaches with heuristic methods. A key lesson is that network de­pen­den­cies and scarce resources must be represented explicitly. Recent work on network con­straints in dis­trib­uted FTQC likewise shows why finite en­tan­gle­ment rates and bandwidth competition matter for fault-tolerant execution.

En­tan­gle­ment is a resource with a lifetime. Producing Bell pairs early can reduce stalls but increases storage exposure; generating them just in time can reduce aging but leave the com­pu­ta­tion waiting. Work on quantum-switch dis­til­la­tion policies illustrates how fidelity, throughput and waiting are interdependent.

A simple example of why minimizing remote gates can mislead

Consider a logical circuit with several operations between two encoded blocks. Placing those blocks together might remove many remote in­ter­ac­tions, but may exceed one processor's data-qubit or ancilla capacity. Distributing them can make every in­ter­ac­tion nonlocal. A third option may place frequently interacting blocks near shared com­mu­ni­ca­tion resources while parallelizing unrelated operations elsewhere. None of these choices can be evaluated from a remote-gate count alone.

What would a good compiler optimize?

Completion time, logical error, com­mu­ni­ca­tion usage and physical-qubit occupancy form a tradeoff. It is possible to shorten a schedule and still make the com­pu­ta­tion less reliable because data spend more time waiting at other points or because a different remote protocol introduces stronger error cor­re­la­tions. My research perspective

I see the op­por­tu­ni­ty in a compiler that explains how an algorithm becomes a fault-tolerant execution on a networked ar­chi­tec­ture. A code library defines supported logical primitives; a hardware model declares available qubits and in­ter­ac­tions; a network service describes en­tan­gle­ment delivery; and an evaluator provides logical-error and resource estimates. The system can then compare different code families and modular configurations on a fair basis. The broader aim is a reproducible connection between abstract logical programs and realistic dis­trib­uted hardware—not merely a reduction in remote-gate count.
