Quantum error correction · November 2026 · 10 min read

What changes when a quantum error-correcting code crosses a network?

The partition itself becomes part of the syndrome circuit and its noise model

The parameters [[n,k,d]] describe an error-correcting code's number of physical qubits, logical qubits and distance. They do not specify how expensive it will be to measure the checks on a particular architecture. This distinction becomes important when data and check ancillas are distributed across processors.

A check is an executed procedure

When every interaction in a stabilizer-measurement circuit remains local, the hardware can use local gates. If a required interaction crosses processors, it needs a remote protocol—often consuming shared entanglement, measurements and feedforward. Such a protocol may introduce additional faults, delays and correlated errors. Two partitions of the same code can consequently have different logical error rates and resource costs.

What noisy color-code seams reveal

Our work on distributed color codes examined the effect of nonuniform errors concentrated around an interface. It provides a useful controlled test of how a code and its decoder react to asymmetric noise. The seam model should not, however, be mistaken for a complete description of a heralded network protocol: waiting time, failed attempts and correlated detector events require further modeling.

Why bivariate bicycle codes matter

Quantum low-density parity-check (qLDPC) codes are appealing because they can encode multiple logical qubits with sparse checks. Bivariate bicycle codes are particularly important in the growing literature on high-rate fault-tolerant memory. However, sparsity of a check does not imply physical locality on a chosen chip or network.

In our modular BB-code study, we analyze the [[144,12,12]] code spread across multiple QPUs and evaluate logical errors with an explicit distinction between local and nonlocal operation noise. The study reports finite-size pseudothreshold behavior under specified assumptions. It is not an asymptotic threshold theorem for arbitrary networks.

Research outlook

I see an opportunity to optimize partitioning, stabilizer-measurement protocols and decoding together. Counting remote interactions is useful, but a smaller cut does not automatically yield lower logical failure if the remaining remote checks are slow or correlated. A meaningful comparison must include the decoder, syndrome schedule and physical network model.

The mathematical picture: checks and distance

A stabilizer code can be written as [[n,k,d]]. The distance d is the minimum weight of a nontrivial logical Pauli operator. In idealized settings, a distance-d code can correct up to ⌊(d−1)/2⌋ arbitrary physical Pauli errors. But this statement does not say how syndrome information is extracted from noisy hardware.

For each stabilizer generator Si, a measurement ideally returns an eigenvalue si ∈ {+1, −1}. A decoder uses the measured syndrome—and in repeated rounds, changes in syndrome—to infer likely errors. In a distributed implementation, the circuit used to obtain si may itself depend on inter-module entanglement. Therefore, it is essential to distinguish the abstract check operator from its physical measurement protocol.

A small example: what does a cut actually cost?

Imagine dividing a code between two QPUs. Suppose most check circuits fit on one QPU but twelve check circuits require cross-module interactions. If each such circuit consumes two Bell pairs, a single syndrome round nominally demands twenty-four remote Bell pairs. This is only an illustrative accounting identity: actual protocols can require fewer or more resources, and parallelism depends on the available communication qubits.

Bround = ∑j ∈ C bjBell-pair budget for one round: C is the set of nonlocal checks and bj is the protocol-specific pair cost of check j. This counts consumption, not retries.

If the network has fewer ports than simultaneous requests, those operations must be scheduled. If a pair is not ready, the round may lengthen and memory noise can increase. Thus the effective cost of a partition is not simply the number of stabilizer edges crossing a boundary; it is a combination of check frequency, protocol, concurrency and noise.

From code-capacity noise to circuit-level noise

A code-capacity model applies noise to data and assumes ideal syndrome information. Circuit-level models additionally include faults in gates, preparations, measurements and idling. Moving from one to the other is necessary if the purpose is to predict performance of a distributed hardware implementation. A model in which nonlocal operations have error rate pnl = αp is a helpful sensitivity study, but α alone does not represent link-generation delay, heralded failures or correlated errors.

For that reason, my preferred workflow is: define the partition; specify the remote check circuit; translate its faults and waiting periods into detector events; run an appropriate decoder; and evaluate logical error and elapsed time. Such a workflow makes clear which conclusions follow from the code itself and which depend on implementation choices.

One conclusion worth keeping in view

The advantage of a high-rate quantum LDPC code is not automatically preserved when we divide it across a network. The right question is whether its encoding advantage survives after accounting for the communication resources and physical circuitry needed to measure its checks. This is where network-aware partitioning and error-correction design meet.
