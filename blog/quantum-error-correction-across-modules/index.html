What changes when a quantum error-correcting code crosses a network?

The partition itself becomes part of the syndrome circuit and its noise model

The parameters [[n,k,d]] describe an error-correcting code's number of physical qubits, logical qubits and distance. They do not specify how expensive it will be to measure the checks on a particular ar­chi­tec­ture. This dis­tinc­tion becomes important when data and check ancillas are dis­trib­uted across processors. Two implementations with identical code parameters can require different numbers of remote in­ter­ac­tions and different amounts of waiting, so their effective circuit-level noise and logical re­li­a­bil­i­ty may differ.

The mathematical picture: checks and distance

A stabilizer code can be written as [[n,k,d]]. The distance d is the minimum weight of a nontrivial logical Pauli operator. In idealized settings, a distance-d code can correct up to ⌊(d−1)/2⌋ arbitrary physical Pauli errors. But this statement does not say how syndrome in­for­ma­tion is extracted from noisy hardware.

For each stabilizer generator Si, a mea­sure­ment ideally returns an eigenvalue si ∈ {+1, −1}. A decoder uses the measured syndrome—and in repeated rounds, changes in syndrome—to infer likely errors. In a dis­trib­uted im­ple­men­ta­tion, the circuit used to obtain si may itself depend on inter-module en­tan­gle­ment. Therefore, it is essential to dis­tin­guish the abstract check operator from its physical mea­sure­ment protocol.

A check is an executed procedure

When every in­ter­ac­tion in a stabilizer-mea­sure­ment circuit remains local, the hardware can use local gates. If a required in­ter­ac­tion crosses processors, it needs a remote protocol—often consuming shared en­tan­gle­ment, mea­sure­ments and feed­for­ward. Such a protocol may introduce additional faults, delays and correlated errors. Two partitions of the same code can con­se­quent­ly have different logical error rates and resource costs.

A small example: what does a cut actually cost?

Imagine dividing a code between two QPUs. Suppose most check circuits fit on one QPU but twelve check circuits require cross-module in­ter­ac­tions. If each such circuit consumes two Bell pairs, a single syndrome round nominally demands twenty-four remote Bell pairs. This is only an il­lus­tra­tive accounting identity: actual protocols can require fewer or more resources, and parallelism depends on the available com­mu­ni­ca­tion qubits.

If the network has fewer ports than simultaneous requests, those operations must be scheduled. If a pair is not ready, the round may lengthen and memory noise can increase. Thus the effective cost of a partition is not simply the number of stabilizer edges crossing a boundary; it is a combination of check frequency, protocol, concurrency and noise.

The code graph and the physical circuit are different objects

A check-operator matrix tells us which data qubits par­tic­i­pate in a stabilizer. It does not say where the check ancilla lives, which physical CNOT order is used, or how a nonlocal operation is im­ple­ment­ed. In particular, a sparse Tanner graph is not au­to­mat­i­cal­ly a local hardware graph. It must be embedded into an ar­chi­tec­ture with a workable mea­sure­ment schedule.

This leads to a dis­tinc­tion between cut edges and network cost. A crossing in the check graph may translate into one or several physical remote in­ter­ac­tions, depending on the circuit, shared ancillas, available com­mu­ni­ca­tion qubits and any en­tan­gle­ment-assisted check protocol. A partition with few crossings might still serialize many checks on one bottleneck. Conversely, a partition with more crossings could run faster if its links operate in parallel.

The decoder also sees the im­ple­men­ta­tion rather than an ideal graph. If an imperfect Bell resource causes related errors at multiple detectors, in­de­pen­dent-error as­sump­tions can underestimate some failure mechanisms. A faithful experiment should report the physical remote protocol, any extra idling, which events are heralded, and how cor­re­la­tions enter the decoder model.

The question I would prioritize is when a code's math­e­mat­i­cal encoding advantage survives its complete physical re­al­iza­tion. That requires comparing error sup­pres­sion, syndrome-round latency and com­mu­ni­ca­tion overhead jointly, not simply dividing the data qubits as evenly as possible. The result should dis­tin­guish the effect of code structure from the effect of the particular partition, physical en­tan­gle­ment protocol and decoder.

What noisy color-code seams reveal

Our work on dis­trib­uted color codes examined the effect of nonuniform errors concentrated around an interface. It provides a useful controlled test of how a code and its decoder react to asymmetric noise. The seam model should not, however, be mistaken for a complete description of a heralded network protocol: waiting time, failed attempts and correlated detector events require further modeling.

Why bivariate bicycle codes matter

Quantum low-density parity-check (qLDPC) codes are appealing because they can encode multiple logical qubits with sparse checks. Bivariate bicycle codes are particularly important in the growing literature on high-rate fault-tolerant memory. However, sparsity of a check does not imply physical locality on a chosen chip or network.

In our modular BB-code study, we analyze the [[144,12,12]] code spread across multiple QPUs and evaluate logical errors with an explicit dis­tinc­tion between local and nonlocal operation noise. The study reports finite-size pseu­dothresh­old behavior under specified as­sump­tions. It is not an asymptotic threshold theorem for arbitrary networks.

From code-capacity noise to circuit-level noise

A code-capacity model applies noise to data and assumes ideal syndrome in­for­ma­tion. Circuit-level models additionally include faults in gates, preparations, mea­sure­ments and idling. Moving from one to the other is necessary if the purpose is to predict per­for­mance of a dis­trib­uted hardware im­ple­men­ta­tion. A model in which nonlocal operations have error rate pnl = αp is a helpful sensitivity study, but α alone does not represent link-generation delay, heralded failures or correlated errors.

For that reason, my preferred workflow is: define the partition; specify the remote check circuit; translate its faults and waiting periods into detector events; run an ap­pro­pri­ate decoder; and evaluate logical error and elapsed time. Such a workflow makes clear which conclusions follow from the code itself and which depend on im­ple­men­ta­tion choices.

One conclusion worth keeping in view

The advantage of a high-rate quantum LDPC code is not au­to­mat­i­cal­ly preserved when we divide it across a network. The right question is whether its encoding advantage survives after accounting for the com­mu­ni­ca­tion resources and physical circuitry needed to measure its checks. This is where network-aware par­ti­tion­ing and error-correction design meet.

Research outlook

I see an op­por­tu­ni­ty to optimize par­ti­tion­ing, stabilizer-mea­sure­ment protocols and decoding together. Counting remote in­ter­ac­tions is useful, but a smaller cut does not au­to­mat­i­cal­ly yield lower logical failure if the remaining remote checks are slow or correlated. A meaningful comparison must include the decoder, syndrome schedule and physical network model.
